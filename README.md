# Эмпирический анализ алгоритма Диница

Проект по дисциплине «Алгоритмы и анализ сложности». Автор - Михеев Григорий Дмитриевич.

Решатель на C++17 находит максимальный поток в ориентированной сети. Генератор создаёт три семейства графов, а программа эксперимента измеряет число проверок остаточных дуг.

- [Диниц отчёт (PDF)](output/pdf/Диниц%20отчёт.pdf) и [исходник LaTeX](output/pdf/Диниц%20отчёт.tex)
- [Диниц презентация (PPTX)](output/Диниц%20презентация.pptx)
- [Графики и данные эксперимента](results/), [схемы](assets/)

## Сборка и запуск

Нужны CMake 3.16 или новее, компилятор с поддержкой C++17 и система сборки, например Make. Команды ниже рассчитаны на Linux и выполняются из корня проекта.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/dinic < example.txt
```

В примере максимальный поток равен `3`. Первая строка входа задаёт `V E s t`, затем идут `E` строк `u v c`, каждая описывает дугу из `u` в `v` с ёмкостью `c`. Вершины нумеруются с нуля. Исток и сток различны. Ёмкости - целые неотрицательные числа, максимальный поток помещается в `int64_t`. Поддерживаются параллельные и встречные дуги. Петли запрещены.

## Генерация графов

```bash
./build/generator random_chain 64 20262560 | ./build/dinic
```

Аргументы генератора задают семейство, число вершин (`V >= 4`) и начальное значение генератора (`seed`, целое от 0 до `2^32 - 1`). Во всех семействах `E = 2 * V - 4`, исток имеет номер `0`, сток - `V - 1`. Ёмкости равномерно выбираются из целых чисел от 1 до 100.

| Семейство | Как выбираются дуги |
|---|---|
| `parallel` | Через каждую промежуточную вершину проводится отдельный двухдуговый путь от истока до стока. |
| `random_chain` | Сначала проводится цепь от истока до стока, затем добавляются случайные дуги. |
| `random_graph` | Дуги выбираются случайно. Набор принимается, если из истока достижим сток. |

Случайные дуги выбираются без петель, повторов, дуг в исток и дуг из стока. Встречные дуги разрешены.
Для `random_graph` достижимость проверяется при генерации, до назначения ёмкостей и запуска решателя.

## Эксперимент

```bash
./build/experiment
```

Эксперимент сравнивает `parallel`, `random_chain` и `random_graph`. Для каждого семейства проверяются шесть размеров от 64 до 2048 вершин, по 40 графов на размер. Все 720 измерений сохраняются в `results/`. Начальное значение вычисляется как `20260000 + 40 * V + trial`, где `trial` идёт от 0 до 39.

- [Отдельные измерения](results/measurements.csv) содержат максимальный поток, число успешных фаз и число проверок для каждого входа. Счётчик увеличивается, когда BFS или DFS проверяет запись остаточной дуги, чтобы решить, можно ли по ней пройти. Учитываются обратные дуги, повторные проверки и заключительный BFS.
- [Сводная таблица](results/summary.csv) содержит 18 строк с показателями для каждой пары «семейство и размер». В ней приведены среднее, исправленное выборочное стандартное отклонение, среднее число фаз, нормировки по `V` и `V^2 * E` и отношение средних при удвоении размера. Для `V = 64` отношение не вычисляется.

[График средних](results/means.png) показывает изменение числа проверок с ростом `V`. [Гистограммы](results/histograms.png) показывают распределения при `V = 256` и `V = 1024`. Чтобы обновить оба файла после запуска эксперимента, нужен gnuplot с поддержкой `pngcairo`.

## Сборка отчёта

Для пересборки PDF нужны `latexmk`, XeLaTeX и шрифты Times New Roman или Tinos, а также DejaVu Sans Mono. В Debian и Ubuntu нужные пакеты - `latexmk`, `texlive-xetex`, `texlive-latex-extra`, `texlive-science`, `texlive-lang-cyrillic`, `fonts-croscore` и `fonts-dejavu-mono`. LaTeX использует графики из `results/`. Новый PDF появится в `build/report/`.

```bash
latexmk -xelatex -outdir=build/report 'output/pdf/Диниц отчёт.tex'
```

- [`experiment.cpp`](src/experiment.cpp) - запуск эксперимента и расчёт статистики.
- [`dinic_main.cpp`](src/dinic_main.cpp) и [`generator_main.cpp`](src/generator_main.cpp) - ввод и вывод для командной строки.
